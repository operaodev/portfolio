## Lo que aprendí en el curso

Completé el curso en su totalidad, validando los contenidos y ejercicios propuestos a lo largo de las 11.5 horas de formación. Partí desde cero y fui construyendo una base sólida de Git hasta llegar a los temas avanzados que se usan en el día a día profesional.

### Fundamentos de Git y control de versiones

Aprendí cómo funciona Git por dentro y por qué es el estándar para el control de versiones. Practiqué la creación de repositorios, el registro de cambios mediante commits y la lectura del historial para entender la evolución de un proyecto.

- Inicialización y configuración de un repositorio
- Ciclo de trabajo con el área de preparación (*staging*) y los commits
- Lectura e interpretación del historial de cambios
- Uso de `.gitignore` para mantener el repositorio limpio

### Gestión del repositorio local y remoto

Trabajé con repositorios locales y remotos, sincronizando cambios y resolviendo los conflictos que aparecen cuando varias personas modifican el mismo proyecto.

- Conexión de un repositorio local con GitHub
- Envío y descarga de cambios con `push`, `pull` y `fetch`
- Gestión de ramas remotas y seguimiento de la rama principal
- Resolución de conflictos de forma ordenada y segura

### Ramas, stash y rebase

Profundicé en las herramientas que permiten trabajar en paralelo sin afectar la línea principal del proyecto y mantener un historial limpio.

- Creación, cambio y fusión de ramas
- Uso de `stash` para guardar trabajo temporal sin hacer commit
- Reorganización del historial con `rebase`
- Viajes en el tiempo para revisar y recuperar estados anteriores del proyecto

### Recuperación en caso de pérdida del proyecto

Aprendí a usar `reflog` y otras técnicas de recuperación para rescatar commits, ramas y cambios que parecían perdidos, ganando confianza para experimentar sin miedo a romper el repositorio.

### GitHub y trabajo en equipo

Utilicé GitHub como repositorio remoto y como plataforma de colaboración, aplicando flujos de trabajo reales de equipo.

- Flujos de trabajo con ramas y Pull Requests
- Revisión de código y gestión de tokens de acceso
- Organización de proyectos, Wikis y GitHub Pages
- Trabajo colaborativo en un mismo proyecto, con Teams, organizaciones y Gists

### Buenas prácticas

Cerré el curso con hábitos que aplico en mis proyectos: commits claros y atómicos, ramas descriptivas, sincronización constante con el remoto y uso del historial como herramienta de recuperación. El objetivo es simple: no volver a perder una sola línea de código, ya sea en programación, diseño web o cualquier otro proyecto.
